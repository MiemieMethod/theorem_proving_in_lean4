2. 依值类型论🔗

依值类型论是一种强大而富有表现力的语言，使你能够表达复杂的数学断言， 编写复杂的硬件与软件规约，并以自然且统一的方式对二者进行推理。 Lean 基于依值类型论的一个版本，即构造演算，并带有可数的、 非累积宇宙层级以及归纳类型。到本章结束时，你将理解这些说法的大部分含义。

2.1. 简单类型论🔗

“类型论”之所以得名，是因为每个表达式都有一个相关联的类型。 例如，在给定上下文中，x + 0 可以表示一个自然数， 而 f 可以表示自然数上的一个函数。对于偏好精确定义的读者， Lean 中的自然数是任意精度的无符号整数。

下面给出一些示例，说明如何在 Lean 中声明对象并检查它们的类型。

/- Define some constants. -/ def m : Nat := 1 -- m is a natural number def n : Nat := 0 def b1 : Bool := true -- b1 is a Boolean def b2 : Bool := false /- Check their types. -/ m : Nat#check m -- m : Nat
m : Nat
n : Nat#check n
n : Nat
n + 0 : Nat#check n + 0 -- n + 0 : Nat
n + 0 : Nat
m * (n + 0) : Nat#check m * (n + 0) -- m * (n + 0) : Nat
m * (n + 0) : Nat
b1 : Bool#check b1 -- b1 : Bool
b1 : Bool
-- "&&" is the Boolean and b1 && b2 : Bool#check b1 && b2 -- b1 && b2 : Bool
b1 && b2 : Bool
-- Boolean or b1 || b2 : Bool#check b1 || b2 -- b1 || b2 : Bool
b1 || b2 : Bool
-- Boolean "true" Bool.true : Bool#check true -- Bool.true : Bool
Bool.true : Bool
/- Evaluate -/ 20#eval 5 * 4 -- 20
20
3#eval m + 2 -- 3
3
false#eval b1 && b2 -- false
false

位于 /- 和 -/ 之间的任何文本构成一个注释块，Lean 会忽略它。 类似地，两个短横线 -- 表明该行余下部分是注释，也会被忽略。 注释块可以嵌套，因此可以像许多编程语言中那样将一大段代码“注释掉”。

def 关键字在工作环境中声明新的常量符号。在上面的示例中， def m : Nat := 1 定义了一个新的常量 m， 其类型为 Nat，值为 1。#check 命令要求 Lean 报告它们的类型；在 Lean 中，查询系统信息的辅助命令通常以井号 (#) 开头。 #eval 命令要求 Lean 对给定表达式求值。你应当自己尝试声明一些常量， 并对若干表达式做类型检查。以这种方式声明新对象，是试验该系统的一种好方法。

简单类型论的强大之处在于，你可以由已有类型构造新类型。例如， 若 a 和 b 是类型，则 a -> b 表示从 a 到 b 的函数类型，而 a × b 表示由一个 a 的元素 与一个 b 的元素配对而成的类型，也称为笛卡尔积。注意， × 是一个 Unicode 符号。审慎使用 Unicode 可以提高可读性， 所有现代编辑器也都很好地支持它。在 Lean 标准库中，你经常会看到用希腊字母表示类型， 并用 Unicode 符号 → 作为 -> 的更紧凑写法。

同样，你应当自己尝试一些示例。

我们来看一些基本语法。你可以通过输入 \to、\r 或 \-> 来输入 Unicode 箭头 →。也可以使用 ASCII 替代写法 ->， 因此表达式 Nat -> Nat 与 Nat → Nat 含义相同。 二者都表示以自然数为输入并以自然数为输出的函数类型。 笛卡尔积的 Unicode 符号 × 可通过 \times 输入。 通常会用小写希腊字母，如 α、β 和 γ，在类型上取值。 这些特定字母可分别通过 \a、\b 和 \g 输入。

这里还有几点需要注意。首先，将函数 f 应用于值 x， 记作 f x（例如 Nat.succ 2）。其次，在书写类型表达式时， 箭头向右结合；例如，Nat.add 的类型是 Nat → Nat → Nat， 它等价于 Nat → (Nat → Nat)。因此，可以把 Nat.add 看成一个函数： 它接受一个自然数，并返回另一个接受自然数且返回自然数的函数。在类型论中， 这通常比把 Nat.add 写成接受一对自然数作为输入并返回自然数的函数更方便。 例如，这允许你对函数 Nat.add 进行“部分应用”。上面的例子表明， Nat.add 3 的类型是 Nat → Nat；也就是说，Nat.add 3 返回一个“等待”第二个参数 n 的函数，这随后等价于写作 Nat.add 3 n。

你已经看到，若有 m : Nat 和 n : Nat，则 (m, n) 表示由 m 和 n 构成的有序对，其类型为 Nat × Nat。 这给出了创建自然数对的一种方式。反过来，若有 p : Nat × Nat， 则可以写 p.1 : Nat 和 p.2 : Nat，这给出了提取其两个分量的方式。

2.2. 作为对象的类型🔗

Lean 的依值类型论扩展简单类型论的一种方式是：类型本身——如 Nat 和 Bool 这样的实体——是一等公民；也就是说，它们自身也是对象。 为使这一点成立，它们每一个也都必须有一个类型。

Nat : Type#check Nat
Nat : Type
Bool : Type#check Bool
Bool : Type
Nat → Bool : Type#check Nat → Bool
Nat → Bool : Type
Nat × Bool : Type#check Nat × Bool
Nat × Bool : Type
Nat → Nat : Type#check Nat → Nat
Nat → Nat : Type
Nat × Nat → Nat : Type#check Nat × Nat → Nat
Nat × Nat → Nat : Type
Nat → Nat → Nat : Type#check Nat → Nat → Nat

(Nat → Nat) → Nat : Type

既然 Lean 中每个表达式都有类型，一个自然的问题是：Type 本身具有何种类型？

Type : Type 1#check Type -- Type : Type 1

你实际上已经触及 Lean 类型系统中最微妙的方面之一。 Lean 的底层基础具有一个无限的类型层级：

可以把 Type 0 看作“小”类型或“普通”类型的宇宙。 于是 Type 1 是一个更大的类型宇宙，它把 Type 0 作为元素包含在内； 而 Type 2 又是一个更大的类型宇宙，它把 Type 1 作为元素包含在内。 这个列表是无限的：对每个自然数 n，都有一个 Type n。 Type 是 Type 0 的缩写：

然而，有些操作需要在类型宇宙上是多态的。例如，对任意类型 α， 无论 α 位于哪个类型宇宙中，List α 都应当有意义。 这解释了函数 List 的类型签名：

List.{u} (α : Type u) : Type u#check List -- List.{u} (α : Type u) : Type u
List.{u} (α : Type u) : Type u

这里 u 是一个在类型层级上取值的变量。#check 命令的输出意味着： 只要 α 的类型是 Type u，List α 的类型也就是 Type u。 函数 Prod 也类似地是多态的：

Prod.{u, v} (α : Type u) (β : Type v) : Type (max u v)#check Prod -- Prod.{u, v} (α : Type u) (β : Type v) : Type (max u v)
Prod.{u, v} (α : Type u) (β : Type v) : Type (max u v)

为定义多态常量，Lean 允许使用 universe 命令显式声明宇宙变量：

universe u def F (α : Type u) : Type u := Prod α α F.{u} (α : Type u) : Type u#check F -- F.{u} (α : Type u) : Type u
F.{u} (α : Type u) : Type u

也可以在定义 F 时给出宇宙参数，从而避免使用 universe 命令：

def F.{u} (α : Type u) : Type u := Prod α α F.{u} (α : Type u) : Type u#check F -- F.{u} (α : Type u) : Type u
F.{u} (α : Type u) : Type u

2.3. 函数抽象与求值🔗

Lean 提供 fun（或 λ）关键字，用于如下从表达式创建函数：

fun x => x + 5 : Nat → Nat#check fun (x : Nat) => x + 5 -- fun x => x + 5 : Nat → Nat
fun x => x + 5 : Nat → Nat
-- λ and fun mean the same thing fun x => x + 5 : Nat → Nat#check λ (x : Nat) => x + 5 -- fun x => x + 5 : Nat → Nat
fun x => x + 5 : Nat → Nat

在这个例子中，类型 Nat 可以被推断出来：

fun x => x + 5 : Nat → Nat#check fun x => x + 5 -- fun x => x + 5 : Nat → Nat
fun x => x + 5 : Nat → Nat
fun x => x + 5 : Nat → Nat#check λ x => x + 5 -- fun x => x + 5 : Nat → Nat
fun x => x + 5 : Nat → Nat

可以通过传入所需参数来对 lambda 函数求值：

15#eval (λ x : Nat => x + 5) 10 -- 15
15

由另一个表达式创建函数的过程称为 lambda 抽象。假设你有变量 x : α， 并且能够构造表达式 t : β，那么表达式 fun (x : α) => t， 或等价地 λ (x : α) => t，就是类型 α → β 的对象。 可以把它看作从 α 到 β 的函数，该函数把任意值 x 映射到值 t。

下面还有一些示例

fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat#check fun x : Nat => fun y : Bool => if not y then x + 1 else x + 2
fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat
fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat#check fun (x : Nat) (y : Bool) => if not y then x + 1 else x + 2
fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat
fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat#check fun x y => if not y then x + 1 else x + 2 -- fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat
fun x y => if (!y) = true then x + 1 else x + 2 : Nat → Bool → Nat

Lean 将最后三个示例解释为同一个表达式；在最后一个表达式中， Lean 从表达式 if not y then x + 1 else x + 2 推断 x 和 y 的类型。

一些数学上常见的函数操作示例可以用 lambda 抽象来描述：

def f (n : Nat) : String := toString n def g (s : String) : Bool := s.length > 0 fun x => x : Nat → Nat#check fun x : Nat => x -- fun x => x : Nat → Nat
fun x => x : Nat → Nat
fun x => true : Nat → Bool#check fun unused variable `x` Note: This linter can be disabled with `set_option linter.unusedVariables false`x : Nat => true -- fun x => true : Nat → Bool
fun x => true : Nat → Bool
fun x => g (f x) : Nat → Bool#check fun x : Nat => g (f x) -- fun x => g (f x) : Nat → Bool
fun x => g (f x) : Nat → Bool
fun x => g (f x) : Nat → Bool#check fun x => g (f x) -- fun x => g (f x) : Nat → Bool
fun x => g (f x) : Nat → Bool

思考这些表达式的含义。表达式 fun x : Nat => x 表示 Nat 上的恒等函数；表达式 fun x : Nat => true 表示总是返回 true 的常值函数； 而 fun x : Nat => g (f x) 表示 f 与 g 的复合。 一般而言，可以省略类型标注，让 Lean 为你推断。因此，例如可以写 fun x => g (f x)，而不写 fun x : Nat => g (f x)。

可以把函数作为参数传入，并通过给它们命名为 f 和 g， 在实现中使用这些函数：

fun g f x => g (f x) : (String → Bool) → (Nat → String) → Nat → Bool#check fun (g : String → Bool) (f : Nat → String) (x : Nat) => g (f x)
fun g f x => g (f x) : (String → Bool) → (Nat → String) → Nat → Bool

也可以把类型作为参数传入：

fun α β γ g f x => g (f x) : (α β γ : Type) → (β → γ) → (α → β) → α → γ#check fun (α β γ : Type) (g : β → γ) (f : α → β) (x : α) => g (f x)
fun α β γ g f x => g (f x) : (α β γ : Type) → (β → γ) → (α → β) → α → γ

例如，最后一个表达式表示这样一个函数：它接受三个类型 α、 β 和 γ，以及两个函数 g : β → γ 和 f : α → β， 并返回 g 与 f 的复合。（理解这个函数的类型需要理解依值积， 这将在下文解释。）

lambda 表达式的一般形式是 fun (x : α) => t，其中变量 x 是一个“绑定变量”：它实际上是一个占位符，其“作用域”不会延伸到表达式 t 之外。 例如，表达式 fun (b : β) (x : α) => b 中的变量 b， 与先前声明的常量 b 没有任何关系。事实上，该表达式表示的函数与 fun (u : β) (z : α) => u 相同。

形式地说，只差绑定变量重命名的表达式称为 alpha 等价，并被认为是“相同的”。 Lean 能识别这种等价。

注意，将项 t : α → β 应用于项 s : α 会得到表达式 t s : β。 回到前面的例子，并为清晰起见重命名绑定变量，请注意以下表达式的类型：

(fun x => x) 1 : Nat#check (fun x : Nat => x) 1 -- (fun x => x) 1 : Nat
(fun x => x) 1 : Nat
(fun x => true) 1 : Bool#check (fun unused variable `x` Note: This linter can be disabled with `set_option linter.unusedVariables false`x : Nat => true) 1 -- (fun x => true) 1 : Bool
(fun x => true) 1 : Bool
def f (n : Nat) : String := toString n def g (s : String) : Bool := s.length > 0 (fun α β γ u v x => u (v x)) Nat String Bool g f 0 : Bool#check (fun (α β γ : Type) (u : β → γ) (v : α → β) (x : α) => u (v x)) Nat String Bool g f 0
(fun α β γ u v x => u (v x)) Nat String Bool g f 0 : Bool

如预期，表达式 (fun x : Nat => x) 1 的类型为 Nat。 事实上，还应当有更强的结论：将表达式 (fun x : Nat => x) 应用于 1 应当“返回”值 1。而它确实如此：

1#eval (fun x : Nat => x) 1 -- 1
1
true#eval (fun unused variable `x` Note: This linter can be disabled with `set_option linter.unusedVariables false`x : Nat => true) 1 -- true
true

稍后你会看到这些项是如何被求值的。现在请注意，这是依值类型论的一个重要特征： 每个项都有计算行为，并支持规范化的概念。原则上，两个能化简到同一值的项称为 定义等价。Lean 的类型检查器会把它们视为“相同”，并尽力识别和支持这些同一性。

Lean 是一门完整的编程语言。它有能够生成二进制可执行文件的编译器， 也有交互式解释器。可以使用命令 #eval 执行表达式， 这是测试函数的首选方式。

2.4. 定义🔗

回顾一下，def 关键字提供了一种声明新的具名对象的重要方式。

def double (x : Nat) : Nat := x + x

如果你了解其他编程语言中的函数工作方式，这看起来可能会更熟悉。 名称 double 被定义为一个函数，它接受一个类型为 Nat 的输入参数 x；调用结果是 x + x，因此返回类型为 Nat。 随后可以这样调用此函数：

def double (x : Nat) : Nat := x + x
6#eval double 3 -- 6
6

在这种情况下，可以把 def 看作一种具名的 fun。 下面的写法得到相同结果：

def double : Nat → Nat := fun x => x + x 6#eval double 3 -- 6
6

当 Lean 有足够信息可以推断类型时，可以省略类型声明。类型推断是 Lean 的重要组成部分：

def double := fun (x : Nat) => x + x

定义的一般形式是 def foo : α := bar，其中 α 是表达式 bar 返回的类型。Lean 通常可以推断类型 α，但显式写出它往往是好习惯。 这会澄清你的意图；如果定义右侧不具有匹配的类型，Lean 会报告错误。

右侧的 bar 可以是任意表达式，而不仅仅是 lambda。 因此，def 也可以像这样仅仅为一个值命名：

def pi := 3.141592654

def 可以接受多个输入参数。下面创建一个将两个自然数相加的函数：

def add (x y : Nat) := x + y 5#eval add 3 2 -- 5
5

参数列表也可以像这样分开书写：

def double (x : Nat) : Nat := x + x
def add (x : Nat) (y : Nat) := x + y 22#eval add (double 3) (7 + 9) -- 22
22

注意，这里我们调用 double 函数来构造传给 add 的第一个参数。

可以在 def 中使用其他更有趣的表达式：

def greater (x y : Nat) := if x > y then x else y

你大概可以猜出这个函数会做什么。

也可以定义一个以另一个函数为输入的函数。下面的函数会调用给定函数两次， 并把第一次调用的输出传给第二次调用：

def double (x : Nat) : Nat := x + x
def doTwice (f : Nat → Nat) (x : Nat) : Nat := f (f x) 8#eval doTwice double 2 -- 8
8

现在再抽象一些，也可以指定类似类型参数的参数：

def compose (α β γ : Type) (g : β → γ) (f : α → β) (x : α) : γ := g (f x)

这意味着 compose 是一个函数，它以任意两个函数作为输入参数， 只要这两个函数各自都只接受一个输入。类型表达式 β → γ 与 α → β 表明有一个要求：第二个函数的输出类型必须与第一个函数的输入类型相匹配。 这是合理的；否则这两个函数就不能复合。

compose 还接受第三个参数，其类型为 α；它用该参数调用第二个函数 （局部命名为 f），并把该函数的结果（类型为 β）作为输入传给第一个函数 （局部命名为 g）。第一个函数返回类型 γ 的值， 因此这也是 compose 函数的返回类型。

compose 也非常通用，因为它适用于任意类型 α β γ。 这意味着，只要两个函数各自接受一个参数，并且第二个函数的输出类型与第一个函数的输入类型相匹配， compose 几乎可以复合任意两个函数。例如：

def compose (α β γ : Type) (g : β → γ) (f : α → β) (x : α) : γ := g (f x) def double (x : Nat) : Nat := x + x
def square (x : Nat) : Nat := x * x 18#eval compose Nat Nat Nat double square 3 -- 18
18

2.5. 局部定义🔗

Lean 也允许使用 let 关键字引入“局部”定义。表达式 let a := t1; t2 与把 t2 中每一次出现的 a 都替换为 t1 所得结果定义等价。

let y := 2 + 2; y * y : Nat#check let y := 2 + 2; y * y -- let y := 2 + 2; y * y : Nat
let y := 2 + 2;
y * y : Nat
16#eval let y := 2 + 2; y * y -- 16
16
def twice_double (x : Nat) : Nat := let y := x + x; y * y 16#eval twice_double 2 -- 16
16

这里，twice_double x 与项 (x + x) * (x + x) 定义等价。

可以通过串联 let 语句来组合多个赋值：

let y := 2 + 2; let z := y + y; z * z : Nat#check let y := 2 + 2; let z := y + y; z * z
let y := 2 + 2;
let z := y + y;
z * z : Nat
64#eval let y := 2 + 2; let z := y + y; z * z -- 64
64

使用换行时，可以省略 ;。

def t (x : Nat) : Nat := let y := x + x y * y

注意，表达式 let a := t1; t2 的含义与 (fun a => t2) t1 的含义非常相近， 但二者并不相同。在第一个表达式中，应把 t2 中每一个 a 都看作 t1 的语法缩写。在第二个表达式中，a 是一个变量， 而表达式 fun a => t2 必须在不依赖 a 的具体值的情况下有意义。 let 构造是一种更强的缩写手段；有些形如 let a := t1; t2 的表达式 不能表示为 (fun a => t2) t1。作为练习，请尝试理解为什么下面 foo 的定义能通过类型检查，而 bar 的定义不能。

def foo := let a := Nat; fun x : a => x + 2 /- def bar := (fun a => fun x : a => x + 2) Nat -/

2.6. 变量与段落🔗

考虑下面三个函数定义：

def compose (α β γ : Type) (g : β → γ) (f : α → β) (x : α) : γ := g (f x) def doTwice (α : Type) (h : α → α) (x : α) : α := h (h x) def doThrice (α : Type) (h : α → α) (x : α) : α := h (h (h x))

Lean 提供 variable 命令，使这类声明看起来更紧凑：

variable (α β γ : Type) def compose (g : β → γ) (f : α → β) (x : α) : γ := g (f x) def doTwice (h : α → α) (x : α) : α := h (h x) def doThrice (h : α → α) (x : α) : α := h (h (h x))

可以声明任意类型的变量，而不仅限于 Type 本身：

variable (α β γ : Type) variable (g : β → γ) (f : α → β) (h : α → α) variable (x : α) def compose := g (f x) def doTwice := h (h x) def doThrice := h (h (h x)) def compose : (α β γ : Type) → (β → γ) → (α → β) → α → γ := fun α β γ g f x => g (f x)#print compose
def compose : (α β γ : Type) → (β → γ) → (α → β) → α → γ :=
fun α β γ g f x => g (f x)
def doTwice : (α : Type) → (α → α) → α → α := fun α h x => h (h x)#print doTwice
def doTwice : (α : Type) → (α → α) → α → α :=
fun α h x => h (h x)
def doThrice : (α : Type) → (α → α) → α → α := fun α h x => h (h (h x))#print doThrice
def doThrice : (α : Type) → (α → α) → α → α :=
fun α h x => h (h (h x))

打印它们会显示，这三组定义具有完全相同的效果。

variable 命令指示 Lean：在按名称引用这些变量的定义中， 把所声明的变量插入为绑定变量。Lean 足够智能，能够判断一个定义中哪些变量被显式或隐式使用。 因此，在书写定义时，你可以像 α、β、γ、 g、f、h 和 x 都是固定对象那样进行， 并让 Lean 自动为你对定义进行抽象。

以这种方式声明时，变量会一直保持在作用域中，直到当前文件结束。 不过，有时限制变量的作用域是有用的。为此，Lean 提供了 section 的概念：

section useful variable (α β γ : Type) variable (g : β → γ) (f : α → β) (h : α → α) variable (x : α) def compose := g (f x) def doTwice := h (h x) def doThrice := h (h (h x)) end useful

当段落关闭时，这些变量离开作用域，不能再被引用。

段落内部的行不必缩进。也不必给段落命名；也就是说，可以使用匿名的 section / end 对。不过，如果给段落命名，就必须使用相同名称关闭它。 段落也可以嵌套，这允许你逐步声明新的变量。

2.8. 依值类型论为何“依值”？🔗

简短的解释是：类型可以依赖于参数的值。你已经见过一个很好的例子： 类型 List α 依赖于参数 α，正是这种依赖区分了 List Nat 和 List Bool。再举一例，考虑类型 Vector α n，它表示长度为 n、元素类型为 α 的向量类型。这个类型依赖于两个参数： 向量中元素的类型（α : Type）以及向量的长度 n : Nat。

假设你想编写函数 cons，用于把一个新元素插入列表头部。 cons 应当具有何种类型？这样的函数是多态的：你期望针对 Nat、 Bool 或任意类型 α 的 cons 函数以同样方式行为。 因此，把类型作为 cons 的第一个参数是合理的；这样，对任意类型 α， cons α 就是类型为 α 的列表的插入函数。换言之，对每个 α， cons α 都是这样一个函数：它接受一个元素 a : α 和一个列表 as : List α，并返回一个新列表，因此有 cons α a as : List α。

显然，cons α 应当具有类型 α → List α → List α。但 cons 本身应当具有何种类型？第一猜想可能是 Type → α → List α → List α， 但仔细想来，这并不合理：此表达式中的 α 没有指向任何东西， 而它本应指向类型为 Type 的那个参数。换句话说，假设 α : Type 是函数的第一个参数，那么接下来两个元素的类型分别是 α 和 List α。 这些类型会随着第一个参数 α 而变化。

def cons (α : Type) (a : α) (as : List α) : List α := List.cons a as cons Nat : Nat → List Nat → List Nat#check cons Nat -- cons Nat : Nat → List Nat → List Nat
cons Nat : Nat → List Nat → List Nat
cons Bool : Bool → List Bool → List Bool#check cons Bool -- cons Bool : Bool → List Bool → List Bool
cons Bool : Bool → List Bool → List Bool
cons (α : Type) (a : α) (as : List α) : List α#check cons -- cons (α : Type) (a : α) (as : List α) : List α
cons (α : Type) (a : α) (as : List α) : List α

这是依值函数类型，或称依值箭头类型的一个实例。给定 α : Type 和 β : α → Type，可以把 β 看作 α 上的一个类型族， 也就是说，对每个 a : α 都有一个类型 β a。在这种情况下， 类型 (a : α) → β a 表示具有如下性质的函数 f 的类型： 对每个 a : α，f a 都是 β a 的一个元素。 换言之，f 返回值的类型依赖于其输入。

注意，对任意表达式 β : Type，(a : α) → β 都有意义。 当 β 的值依赖于 a 时（例如上一段中的表达式 β a）， (a : α) → β 表示一个依值函数类型。当 β 不依赖于 a 时， (a : α) → β 与类型 α → β 没有区别。事实上，在依值类型论 （以及 Lean）中，当 β 不依赖于 a 时， α → β 只是 (a : α) → β 的记号。

回到列表的例子，可以使用命令 #check 查看以下 List 函数的类型。 @ 符号以及圆括号与花括号之间的区别稍后会解释。

@List.cons : {α : Type u_1} → α → List α → List α#check @List.cons -- @List.cons : {α : Type u_1} → α → List α → List α
@List.cons : {α : Type u_1} → α → List α → List α
@List.nil : {α : Type u_1} → List α#check @List.nil -- @List.nil : {α : Type u_1} → List α
@List.nil : {α : Type u_1} → List α
@List.length : {α : Type u_1} → List α → Nat#check @List.length -- @List.length : {α : Type u_1} → List α → Nat
@List.length : {α : Type u_1} → List α → Nat
@List.append : {α : Type u_1} → List α → List α → List α#check @List.append -- @List.append : {α : Type u_1} → List α → List α → List α

正如依值函数类型 (a : α) → β a 通过允许 β 依赖于 a 来推广函数类型 α → β 一样，依值笛卡尔积类型 (a : α) × β a 也以同样方式推广笛卡尔积 α × β。 依值积也称为 sigma 类型，并且也可以写作 Σ a : α, β a。 可以使用 ⟨a, b⟩ 或 Sigma.mk a b 创建依值对。字符 ⟨ 和 ⟩ 可分别通过 \langle 与 \rangle 或 \< 与 \> 输入。

universe u v def f (α : Type u) (β : α → Type v) (a : α) (b : β a) : (a : α) × β a := ⟨a, b⟩ def g (α : Type u) (β : α → Type v) (a : α) (b : β a) : Σ a : α, β a := Sigma.mk a b def h1 (x : Nat) : Nat := (f Type (fun α => α) Nat x).2 5#eval h1 5 -- 5
5
def h2 (x : Nat) : Nat := (g Type (fun α => α) Nat x).2 5#eval h2 5 -- 5
5

上面的函数 f 与 g 表示同一个函数。

然而，输入所有这些下划线仍然很繁琐。当一个函数接受的某个参数通常可以从上下文推断时， Lean 允许你指定该参数默认应保持隐式。做法是把这些参数放在花括号中，如下所示：

universe u def Lst (α : Type u) : Type u := List α def Lst.cons {α : Type u} (a : α) (as : Lst α) : Lst α := List.cons a as def Lst.nil {α : Type u} : Lst α := List.nil def Lst.append {α : Type u} (as bs : Lst α) : Lst α := List.append as bs Lst.cons 0 Lst.nil : Lst Nat#check Lst.cons 0 Lst.nil
Lst.cons 0 Lst.nil : Lst Nat
def as : Lst Nat := Lst.nil def bs : Lst Nat := Lst.cons 5 Lst.nil as.append bs : Lst Nat#check Lst.append as bs
as.append bs : Lst Nat

唯一改变的是变量声明中 α : Type u 周围的括号。也可以在函数定义中使用这种机制：

universe u def ident {α : Type u} (x : α) := x

检查 ident 的类型时，需要将其置于圆括号中，以避免显示其签名：

这使 ident 的第一个参数成为隐式参数。从记号上看， 这隐藏了对类型的指定，使 ident 看起来仿佛只是接受任意类型的一个参数。 事实上，标准库中的函数 id 正是以这种方式定义的。这里选择一个非传统名称， 只是为了避免名称冲突。

使用 variable 命令声明变量时，也可以把它们指定为隐式的：

universe u section variable {α : Type u} variable (x : α) def ident := x end ident.{u} {α : Type u} (x : α) : α#check ident

这里对 ident 的定义与上面的定义具有相同效果。

Lean 具有非常复杂的机制来实例化隐式参数；我们将看到，它们可用于推断函数类型、 谓词，甚至证明。实例化项中的这些“空洞”或“占位符”的过程通常称为阐释。 隐式参数的存在意味着，有时可能没有足够信息来精确确定一个表达式的含义。 像 id 或 List.nil 这样的表达式称为多态的， 因为它可以在不同上下文中具有不同含义。

总可以通过写 (e : T) 来指定表达式 e 的类型 T。 这会指示 Lean 的阐释器在尝试解析隐式参数时，把值 T 用作 e 的类型。 在下面第二组示例中，这一机制用于指定表达式 id 和 List.nil 的期望类型：

[] : List ?m.1#check (List.nil) -- [] : List ?m.2
[] : List ?m.1
id : ?m.1 → ?m.1#check (id) -- id : ?m.1 → ?m.1
id : ?m.1 → ?m.1
[] : List Nat#check (List.nil : List Nat) -- [] : List Nat
[] : List Nat
id : Nat → Nat#check (id : Nat → Nat) -- id : Nat → Nat
id : Nat → Nat

Lean 中的数码是重载的；但当无法推断一个数码的类型时，Lean 默认假定它是自然数。 因此，下面前两个 #check 命令中的表达式会以相同方式阐释， 而第三个 #check 命令将 2 解释为整数。

2 : Nat#check 2 -- 2 : Nat
2 : Nat
2 : Nat#check (2 : Nat) -- 2 : Nat
2 : Nat
2 : Int#check (2 : Int) -- 2 : Int
2 : Int

然而，有时会遇到这样的情况：我们已经把函数的某个参数声明为隐式， 但现在又想显式提供该参数。如果 foo 是这样的函数，记号 @foo 表示同一个函数，只是所有参数都变为显式。

@id : {α : Sort u_1} → α → α#check @id -- @id : {α : Sort u_1} → α → α
@id : {α : Sort u_1} → α → α
id : Nat → Nat#check @id Nat -- id : Nat → Nat
id : Nat → Nat
id : Bool → Bool#check @id Bool -- id : Bool → Bool
id : Bool → Bool
id 1 : Nat#check @id Nat 1 -- id 1 : Nat
id 1 : Nat
id true : Bool#check @id Bool true -- id true : Bool
id true : Bool

注意，现在第一个 #check 命令给出了标识符 id 的类型， 且没有插入任何占位符。此外，输出表明第一个参数是隐式的。
